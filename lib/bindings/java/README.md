# mathutils — Java/JNI bindings

Plain Java bindings for the `mathutils` C++ library, generated by
[SWIG](https://www.swig.org/). Nothing here is Android-specific: the generated
Java is ordinary JVM code in package `com.example.mathutils`, and the generated
C++ is an ordinary JNI wrapper. It lives with the library so any consumer (the
Compose app in `app/`, a desktop JVM program, another app) reuses the same
binding instead of carrying its own copy.

## Layout

```
lib/bindings/java/
├── CMakeLists.txt         # SWIG generation + libmathutils_jni (+ optional jar)
├── mathutils.i            # the only hand-written file: the SWIG interface
└── generated/             # SWIG output (git-ignored)
    ├── java/com/example/mathutils/{MathNative,MathNativeJNI,LongVector}.java
    └── cpp/mathutils_wrap.cxx
```

`mathutils.i` `%include`s the library's public headers, so the headers stay the
single source of truth for the API.

## Standalone build (no Android)

Requires `swig` and a JDK (for `jni.h`):

```sh
cmake -S lib/bindings/java -B lib/bindings/java/build -DMATHUTILS_JAVA_BUILD_JAR=ON
cmake --build lib/bindings/java/build
```

That runs SWIG, compiles `libmathutils_jni.so` (linking `lib/`'s own CMake
targets), and — with `MATHUTILS_JAVA_BUILD_JAR=ON` — compiles the proxies into
`mathutils.jar`. Smoke-test it from plain Java:

```sh
java -cp lib/bindings/java/build/mathutils.jar:. \
     -Djava.library.path=lib/bindings/java/build T
```

Options:

| Option / variable            | Default                 | Meaning                                        |
| ---------------------------- | ----------------------- | ---------------------------------------------- |
| `MATHUTILS_JAVA_RUN_SWIG`    | `ON`                    | Run SWIG as part of this build                 |
| `MATHUTILS_JAVA_BUILD_JAR`   | `OFF`                   | Also compile the proxies into `mathutils.jar`  |
| `MATHUTILS_JAVA_PACKAGE`     | `com.example.mathutils` | Java package for the generated classes         |
| `MATHUTILS_JAVA_GENERATED_DIR` | `./generated`         | Where SWIG output is written / read from       |

## Android build

The app configures this same project as its `externalNativeBuild.cmake.path`,
once per ABI, with `-DMATHUTILS_JAVA_RUN_SWIG=OFF`: Gradle's `:app:generateSwig`
task runs SWIG once up front instead, so the parallel per-ABI builds cannot race
regenerating the same files. Gradle then adds `generated/java` to the app's Java
source set. See `docs/swig-jni-integration.md` for the full walkthrough.

To regenerate by hand:

```sh
swig -c++ -java \
  -package com.example.mathutils \
  -Ilib/include \
  -outdir lib/bindings/java/generated/java/com/example/mathutils \
  -o lib/bindings/java/generated/cpp/mathutils_wrap.cxx \
  lib/bindings/java/mathutils.i
```
